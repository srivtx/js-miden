# Critique Report: Project 2 — Secure File Vault

**Reviewer:** Senior Technical Critic Agent  
**Date:** 2026-05-06  
**File Reviewed:** `/docs_js_backend/projects/02-secure-file-vault/README.md`

---

## Executive Summary

This project has the most **dangerous gap between ambition and implementation**. It promises "AES-256-GCM at rest" and "secure file storage for a legal firm," but the core encryption flow is **completely broken** in the step-by-step code. The streaming encryption example cannot be used to decrypt files. Combined with a public S3 bucket in the Docker setup, missing auth, and a fundamentally wrong understanding of Multer streaming, this guide would get a legal firm breached and fined.

---

## CRITICAL (Will cause data loss or breaches if copied)

### C1. Encryption Metadata is Hardcoded Garbage — Files Will Be Unrecoverable
- **Location:** `src/routes/upload.ts` (Step 2)
- **Issue:** After streaming encryption, the code does:
  ```typescript
  const salt = 'extracted_salt'; // Simplified
  const iv = 'extracted_iv';     // Simplified
  ```
  These literal strings are stored in the database. When decryption is attempted, `createDecipheriv` will fail because `'extracted_salt'` is not the 32-byte salt used to derive the key, and `'extracted_iv'` is not the 16-byte IV generated by `createEncryptStream`.
- **Impact:** **Every file encrypted with this code is permanently unrecoverable.** A learner who copies this will discover they cannot download their own files.
- **Fix Required:** The `createEncryptStream` function MUST expose the generated `salt` and `iv` via a property or event so the route can capture them. Or use a header-prepended format and parse it on decryption. The current code is non-functional.

### C2. `createEncryptStream` Does Not Include the Auth Tag in a Recoverable Format
- **Location:** `src/utils/encryption.ts` (Section 3)
- **Issue:** The auth tag is appended at the end of the stream via `this.push(cipher.getAuthTag())`. This is fine, but there is **no corresponding decryption stream** shown that reads and verifies this tag. The guide only shows `decryptBuffer`, not a streaming decryptor.
- **Impact:** For 2GB files, you MUST stream decryption. The guide provides no way to do so. Learners will try to use `decryptBuffer` on a 2GB file and crash the server with an OOM.
- **Fix Required:** Provide a `createDecryptStream` that reads the prepended salt/IV and trailing auth tag.

### C3. MinIO Bucket is Made Public in Docker Compose
- **Location:** `scripts/setup-minio.sh` + `docker-compose.yml`
- **Issue:** `mc anonymous set download local/vault-files` makes the bucket world-readable. The guide adds a comment saying "NEVER make buckets public," but the script is part of the project's copy-paste path. The `docker-compose.yml` does not even run this script, but if a learner follows the setup instructions, they may copy it.
- **Impact:** Anyone with the bucket URL can list and download all files without any pre-signed URL.
- **Fix Required:** Remove the `mc anonymous set download` line entirely. Add a healthcheck dependency that ensures the bucket exists as private.

### C4. No Authentication Implementation Shown
- **Location:** `src/routes/upload.ts`, `src/routes/download.ts`, `src/middleware/auth.ts`
- **Issue:** The code casts `req as any).user` everywhere. The `requireRole` middleware checks a `user` property that is never populated by any passport/JWT/OAuth code. There is no login endpoint, no token validation, no session management.
- **Impact:** A learner deploying this has **zero access control**. Anyone can upload, download, and delete files.
- **Fix Required:** Include a complete auth middleware using JWT or session cookies. Show token validation.

### C5. `multer({ storage: undefined })` Does NOT Stream — It Buffers in Memory
- **Location:** `src/middleware/upload.ts`
- **Issue:** The guide claims `storage: undefined` means streaming. In Multer, `undefined` falls back to the default storage engine, which is **memory storage** in some versions or disk storage in others. Either way, it does NOT give you a stream in `req.file`. The subsequent code does `req.body.fileStream as ReadableStream`, which is fantasy—Multer puts parsed fields on `req.body` and files on `req.file` (as buffers or disk paths), not streams.
- **Impact:** A learner who copies this will buffer 2GB files in RAM and crash. The entire promise of streaming is broken.
- **Fix Required:** Use `busboy` or `formidable` with streaming, or show `@aws-sdk/lib-storage` with a stream sourced from `busboy`. Do not use Multer for this use case.

### C6. Audit Log Monkey-Patches `res.end` Incorrectly
- **Location:** `src/middleware/audit.ts`
- **Issue:** The middleware replaces `res.end`, calls the original, then performs async work (`logAuditEvent`). If the server crashes between `res.end` and the DB write, the audit log is lost. Worse, `res.end` is called synchronously but the audit write is async—if the event loop is saturated, the write may be delayed indefinitely.
- **Impact:** Compliance failure. Legal firms require guaranteed audit trails. This is fire-and-forget with no guarantee.
- **Fix Required:** Use a message queue (Bull, as mentioned elsewhere) for ALL audit events. Do not rely on post-response async work.

## MAJOR (Outdated, inefficient, or missing robustness)

### M1. No Transaction Between S3 Upload and DB Record
- **Location:** `src/routes/upload.ts`
- **Issue:** S3 upload completes, THEN DB record is created. If the DB insert fails (connection dropped, validation error), the file exists in S3 as an orphan with no metadata. There is no cleanup.
- **Fix Required:** Use a two-phase pattern: create DB record with `status: PENDING_UPLOAD`, upload to S3, then update status to `PENDING_SCAN`. Cleanup job reaps `PENDING_UPLOAD` records older than N minutes.

### M2. `node-cron` Used But Never Listed in Dependencies
- **Location:** `src/jobs/cleanup.ts`
- **Issue:** `import { schedule } from 'node-cron'` appears in the code, but `node-cron` is not in the `pnpm add` command or `package.json`. Learners will get a module not found error.

### M3. Cleanup Job Loads All Expired Files into Memory
- **Location:** `src/jobs/cleanup.ts`
- **Issue:** `db.file.findMany({ where: { expiresAt: { lt: new Date() } } })` fetches every expired file at once. If 100,000 files expired, this loads their entire records into memory.
- **Fix Required:** Use pagination (`skip`/`take` or cursor-based) or delete in batches.

### M4. `MASTER_KEY` Loaded with Non-Null Assertion
- **Location:** `src/routes/upload.ts`
- **Issue:** `Buffer.from(process.env.ENCRYPTION_MASTER_KEY!, 'base64')` will throw an opaque error at runtime if the env var is missing. The `!` hides the problem from TypeScript.
- **Fix Required:** Validate env vars at startup. Fail fast with a descriptive error.

### M5. Prisma Client Import Path is Inconsistent
- **Location:** Multiple files
- **Issue:** Some files import `db` from `../db/client.js`, others from `../db`. The schema defines `@@map("access_logs")` but the code uses `db.accessLog.create()`. If the Prisma client isn't generated with exact camelCase, this breaks.

### M6. Dockerfile is Incomplete
- **Location:** `Dockerfile`
- **Issue:** The Dockerfile ends with `EXPOSE 3000` and no `CMD` or `ENTRYPOINT`. The container will start and immediately exit.
- **Fix Required:** Add `CMD ["node", "dist/index.js"]` or similar.

## MINOR (Typos, inconsistencies, papercuts)

### m1. `db` vs `prisma` Naming Inconsistency
- The schema and some snippets use `prisma`, but the route code uses `db`. Pick one.

### m2. `AccessLog` Model Has No `firmId` Column
- The requirements specify role-based access per firm, but audit logs have no `firmId`, making firm-level compliance queries impossible.

### m3. `upload.done()` Not Shown with Error Handling
- If S3 upload fails mid-stream, the error propagates but the encrypt stream may leave partial data. No discussion of aborting multipart uploads.

## MISSING (Important topics not covered)

### X1. File Integrity Checksums (SHA-256)
- No checksum is calculated before or after upload. A network blip could corrupt a file, and the user would never know until they try to open it.

### X2. Decryption Endpoint
- There is no route showing how to download, stream-decrypt, and send the file to the user. The guide ends at "here's a pre-signed URL to the ciphertext." Users cannot actually use their files.

### X3. Key Rotation for Existing Files
- Bug 2 discusses key rotation conceptually, but provides no migration path for re-encrypting existing files when a key is rotated.

### X4. ClamAV Integration
- The virus scanning section is entirely a simulation (`isInfected = false`). For a legal firm, this is unacceptable. At minimum, provide a working ClamAV docker-compose service and a real stream-to-clamd implementation.

### X5. TLS / HTTPS Configuration
- The requirements say "TLS 1.3 for all API calls." The guide never mentions HTTPS, certificates, or TLS termination.

### X6. File Download Stream Decryption
- Completely missing. The guide talks about pre-signed URLs but the files are encrypted. The user would download ciphertext.
