# M14 UUID Generator: Fundamentals

## Strip the Libraries. Implement from Scratch.

You are not allowed to use `crypto.randomUUID()`, the `uuid` npm package, or any external UUID library. You have:

- Node.js built-in `crypto`
- Node.js built-in `http`

Build an HTTP server that generates RFC 4122-compliant UUID v4 values and validates them using a strict regex.

## The Constraints

1. Use `crypto.randomBytes(16)` to generate 16 bytes of randomness from the OS CSPRNG.
2. Set the version nibble (bits 48-51) to `0100` (hex `4`).
3. Set the variant nibble (bits 64-67) to `10xx` (hex `8`, `9`, `a`, or `b`).
4. Format the 128 bits into the standard `xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx` string.
5. Validate incoming UUIDs with a strict regex that checks version, variant, and hex characters.
6. Generation must complete in < 1 ms.

```javascript
const http = require('http');
const crypto = require('crypto');

function generateUUID() {
  const bytes = crypto.randomBytes(16);

  // Version (4) in bits 48-51 → byte 6, high nibble
  bytes[6] = (bytes[6] & 0x0f) | 0x40;

  // Variant (10xx) in bits 64-67 → byte 8, high nibble
  bytes[8] = (bytes[8] & 0x3f) | 0x80;

  const hex = bytes.toString('hex');
  return [
    hex.slice(0, 8),
    hex.slice(8, 12),
    hex.slice(12, 16),
    hex.slice(16, 20),
    hex.slice(20, 32),
  ].join('-');
}

const UUID_V4_REGEX =
  /^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$/i;

function isValidUUID(uuid) {
  return UUID_V4_REGEX.test(uuid);
}

const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'application/json' });

  if (req.url === '/generate' && req.method === 'POST') {
    res.end(JSON.stringify({ uuid: generateUUID() }));
  } else if (req.url.startsWith('/validate/') && req.method === 'GET') {
    const uuid = req.url.slice('/validate/'.length);
    res.end(JSON.stringify({ uuid, valid: isValidUUID(uuid) }));
  } else {
    res.writeHead(404);
    res.end(JSON.stringify({ error: 'Not found' }));
  }
});

server.listen(3000);
```

**Key techniques:**
- **Bitmasking**: `bytes[6] = (bytes[6] & 0x0f) | 0x40` preserves the low nibble and sets the high nibble to `0100`.
- **CSPRNG**: `crypto.randomBytes` reads from `/dev/urandom` or equivalent. It is slow enough to be secure, fast enough to be practical.
- **Strict validation**: The regex rejects wrong versions, wrong variants, and invalid hex characters in a single test.

## Why This Matters

Frameworks hide the bit layout. But when a security audit asks "How do you know your UUIDs are actually random?" you need to answer in bits and bytes. The version and variant nibbles exist for a reason: they prove the UUID was generated by a compliant algorithm. Without them, a UUID is just a 36-character string.
