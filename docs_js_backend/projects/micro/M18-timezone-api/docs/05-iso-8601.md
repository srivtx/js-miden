# ISO 8601

## WHAT

**ISO 8601** is the international standard for representing dates, times, and durations. The most common profile for APIs is:

```
YYYY-MM-DDTHH:mm:ss.sssZ
```

- `T` separates date and time.
- `Z` (Zulu) indicates UTC (`+00:00`).
- Milliseconds are optional but recommended for precision.

Examples:

- `2024-06-15T14:00:00Z` — UTC.
- `2024-06-15T16:00:00+02:00` — Local time with explicit offset.

## WHY

Ambiguous date formats cause data corruption and integration failures:

- `03/04/2024` is March 4 in the US, April 3 in the UK.
- `2024-06-15` is a date; `2024-06-15T00:00:00Z` is an instant. Mixing them causes off-by-one-day bugs when timezone conversion is applied.
- ISO 8601 is **lexicographically sortable**, making it ideal for database indexing and cursor pagination.

## HOW

**In JavaScript:**

```javascript
const now = new Date();
console.log(now.toISOString()); // "2024-06-15T14:00:00.000Z"

// Parsing ISO 8601 is safe and unambiguous
const d = new Date("2024-06-15T14:00:00Z"); // Reliable
```

**In API contracts:**

- Accept only ISO 8601 for datetime fields.
- Reject ambiguous strings with `400 Bad Request`.
- Include timezone offset if the instant has local significance.

```javascript
const schema = z.object({
  dueDate: z.string().datetime({ message: "Must be ISO 8601" })
});
```

## WRONG vs RIGHT

### WRONG: Locale-Dependent Strings

```javascript
// BAD: Ambiguous and non-sortable
const due = "06/15/2024 2:00 PM"; // US format? 12h clock?
await db.todo.create({ data: { dueDate: due } });
```

### RIGHT: ISO 8601 UTC

```javascript
// GOOD: Unambiguous, sortable, globally understood
const due = "2024-06-15T14:00:00Z";
await db.todo.create({ data: { dueDate: due } });
```

## Breach Story: NHS Digital Patient Records (2010)

In 2010, a UK National Health Service IT migration project used American date formatting (`MM/DD/YYYY`) in a system expecting British format (`DD/MM/YYYY`). This caused the records of over 8,000 patients to be mismatched with incorrect appointment dates and medication schedules. The incident delayed a £12B program and required manual reconciliation. Root cause: ambiguous date strings without an ISO 8601 mandate.
